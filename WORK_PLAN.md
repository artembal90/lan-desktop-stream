# 1. Оптимизация и контроль нагрузки на сеть 🔴

**Главная цель:** приложение не должно перегружать LAN и мешать другим сетевым программам.

### 1.1 Контроль bitrate

- [ ] Проверить, как фактический WebRTC encoder применяет установленный bitrate.
- [ ] Реализовать реальное ограничение bitrate через WebRTC encoding parameters.
- [ ] Разделить `target bitrate` и `actual bitrate`.
- [ ] Показывать фактический исходящий трафик.

### 1.2 Профили качества

- [ ] Экономичный профиль.
- [ ] Сбалансированный профиль.
- [ ] Качество.
- [ ] Максимум.
- [ ] Разумное значение по умолчанию: 1080p / 30 FPS / около 6 Mbps.

### 1.3 Общий сетевой лимит

- [ ] Добавить настройку максимального общего исходящего трафика.
- [ ] Ограничивать суммарный трафик всех receiver.
- [ ] Не позволять подключению новых receiver превысить общий лимит.
- [ ] Динамически распределять доступный bandwidth между receiver.

### 1.4 Ограничение на receiver

- [ ] Рассчитывать доступный bitrate для каждого receiver.
- [ ] Перераспределять bandwidth при подключении/отключении receiver.
- [ ] Корректно работать при большом количестве receiver.

### 1.5 Adaptive bitrate

- [ ] Собирать packet loss.
- [ ] Собирать RTT.
- [ ] Собирать jitter.
- [ ] Определять ухудшение качества сети.
- [ ] Автоматически снижать bitrate при перегрузке.
- [ ] Постепенно повышать bitrate после восстановления сети.
- [ ] Не допускать резких колебаний bitrate.

### 1.6 Adaptive FPS

- [ ] Добавить управление FPS в зависимости от состояния сети.
- [ ] При перегрузке снижать FPS до 45/30.
- [ ] После восстановления возвращать исходный FPS.
- [ ] Проверить целесообразность режимов 90/120/144 FPS.

### 1.7 Экономия трафика для рабочего стола

- [ ] Исследовать поведение encoder при статичном экране.
- [ ] Настроить параметры для снижения среднего bitrate при отсутствии изменений.
- [ ] Не ухудшать заметно качество при активном движении/смене окон.

### 1.8 UI и диагностика сети

- [ ] Показывать установленный лимит.
- [ ] Показывать фактический общий TX bitrate.
- [ ] Показывать TX bitrate каждого receiver.
- [ ] Показывать предупреждение при приближении к лимиту.
- [ ] Показывать состояние adaptive controller.

### 1.9 Тесты этапа 1

- [ ] 1 receiver.
- [ ] 2 receiver.
- [ ] 5 receiver.
- [ ] Подключение/отключение receiver во время трансляции.
- [ ] Ограничение общего трафика 5 Mbps.
- [ ] Ограничение общего трафика 10 Mbps.
- [ ] Ограничение общего трафика 15 Mbps.
- [ ] Искусственное ухудшение сети.
- [ ] Восстановление сети.
- [ ] Проверить, что другие сетевые программы сохраняют нормальную работу.
- [ ] Проверить отсутствие резких скачков TX traffic.

**Критерий завершения этапа:** приложение работает в заданном сетевом бюджете и автоматически адаптирует качество, не создавая неконтролируемой нагрузки на LAN.

# 2. Базовая стабильность 🔴

**Цель:** сохранить текущую стабильную работу и устранить потенциальные проблемы lifecycle.

### 2.1 WebRTC lifecycle

- [ ] Проверить состояния PeerConnection.
- [ ] Корректно закрывать PeerConnection.
- [ ] Исключить зависшие соединения.
- [ ] Проверить reconnect.
- [ ] Проверить duplicate sessions.

### 2.2 Start / Stop

- [ ] Ввести явные состояния IDLE / STARTING / RUNNING / STOPPING.
- [ ] Исключить конфликтующие Start/Stop операции.
- [ ] Проверить корректность состояния кнопок.
- [ ] Проверить очистку ресурсов после Stop.

### 2.3 Receiver

- [ ] Проверить refresh страницы.
- [ ] Проверить повторное подключение.
- [ ] Проверить отключение receiver.
- [ ] Проверить длительную работу.
- [ ] Проверить несколько receiver одновременно.

### 2.4 Ресурсы

- [ ] Проверить таймеры.
- [ ] Проверить event listeners.
- [ ] Проверить WebSocket connections.
- [ ] Проверить память после длительной работы.
- [ ] Проверить отсутствие resource leaks.

**Критерий завершения этапа:** многократные Start/Stop/reconnect/refresh не приводят к зависаниям, чёрному экрану, duplicate receiver или утечкам ресурсов.
