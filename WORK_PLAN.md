# 1. Оптимизация и контроль нагрузки на сеть 🔴

**Главная цель:** приложение не должно перегружать LAN и мешать другим сетевым программам.

### 1.1 Контроль bitrate

- [x] Проверить текущую схему применения bitrate: исходная версия передавала только конфигурационное значение, без гарантированного лимита WebRTC encoder.
- [x] Реализовать реальное ограничение bitrate через WebRTC encoding parameters (`RTCRtpSender.setParameters`, `encodings[].maxBitrate`).
- [x] Разделить `target bitrate` и `actual bitrate`: target задаётся профилем/лимитом, actual считается по `outbound-rtp.bytesSent`.
- [x] Показывать фактический исходящий трафик в диагностике.

### 1.2 Профили качества

- [x] Экономичный профиль — 3.5 Mbps / 30 FPS.
- [x] Сбалансированный профиль — 6 Mbps / 30 FPS.
- [x] Качество — 10 Mbps / 60 FPS.
- [x] Максимум — 18 Mbps / 60 FPS.
- [x] Значение по умолчанию: 1080p / 30 FPS / 6 Mbps.

### 1.3 Общий сетевой лимит

- [x] Добавить настройку максимального общего исходящего трафика.
- [x] Ограничивать суммарный трафик всех receiver через распределение общего бюджета.
- [x] Не позволять подключению нового receiver автоматически превысить заданный общий лимит: доступный bitrate пересчитывается как `totalBitrate / receiverCount`.
- [x] Динамически перераспределять доступный bandwidth между receiver.

### 1.4 Ограничение на receiver

- [x] Рассчитывать доступный bitrate для каждого receiver.
- [x] Перераспределять bandwidth при подключении/отключении receiver.
- [x] Учитывать одновременно профильный лимит и общий лимит: применяется минимум из двух значений.
- [x] Ограничение задаётся непосредственно на WebRTC video sender каждого PeerConnection.

### 1.5 Adaptive bitrate

- [x] Собирать packet loss из WebRTC stats.
- [x] Собирать RTT из `remote-inbound-rtp`.
- [x] Собирать jitter из `remote-inbound-rtp`.
- [x] Определять ухудшение качества по RTT/jitter/loss.
- [x] Автоматически снижать bitrate при обнаруженной деградации до 75% от текущего бюджета.
- [x] Постепенно возвращать bitrate после восстановления сети.
- [x] Ввести защиту от резких колебаний: изменение состояния не чаще одного раза в 6 секунд.

### 1.6 Adaptive FPS

- [x] Добавить управление FPS через `MediaStreamTrack.applyConstraints`.
- [x] При перегрузке снижать FPS до 30.
- [x] После восстановления возвращать выбранный пользователем FPS.
- [x] Профили качества больше не требуют 90/120/144 FPS по умолчанию; они остаются ручными значениями, если пользователь их выберет.

### 1.7 Экономия трафика для рабочего стола

- [x] Для desktop capture установлен `contentHint='detail'`, чтобы явно сообщить encoder характер содержимого.
- [ ] Исследовать поведение encoder при полностью статичном экране на реальном Windows encoder.
- [ ] Подтвердить средний bitrate при отсутствии изменений и при активном движении.
- [ ] Проверить, что оптимизация не ухудшает заметно качество.

### 1.8 UI и диагностика сети

- [x] Показывать установленный общий лимит.
- [x] Показывать распределение бюджета по receiver.
- [x] Показывать фактический общий TX bitrate в диагностике.
- [x] Показывать TX bitrate каждого receiver в диагностических данных.
- [x] Показывать состояние adaptive controller.
- [x] Показывать RTT, jitter и packet loss для receiver.
- [x] Показывать фактический/effective FPS каждого receiver отдельно от выбранного FPS.
- [x] Для effective FPS использовать `framesPerSecond`, а при отсутствии/нулевом значении — расчёт по `framesSent` за интервал.
- [x] Считать packet loss для adaptive по интервалу (`lossDelta`/`lossRate`), а не только по накопительному счётчику.
- [x] Не выполнять дополнительный `getStats()` в adaptive controller, если актуальная выборка уже собрана.
- [x] Защитить сбор статистики от перекрывающихся/дублирующих вызовов.
- [x] Добавить облегчённое периодическое логирование per-receiver bitrate/FPS и aggregate TX.
